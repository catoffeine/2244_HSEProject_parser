# Парсер ЭКБ

Парсер собирает артикулы, характеристики и ссылки на даташиты из каталога YAGEO Group. Сбор можно продолжить после остановки, просмотреть в локальном веб-интерфейсе и выгрузить в CSV, JSONL или SQLite. Матрица аналитиков определяет, какие характеристики нужны для каждой группы.

Сейчас проект поддерживает сбор, сопоставление параметров, контроль заполненности и экспорт. Интеграция с PostgreSQL и конечный SQLite по схеме АСОНИКИ-К-СЧ пока в плане.

## Установка

Для установки проекта нужен **uv**. Его можно установить без Python. Проект требует **Python 3.12 или новее**. Если Python не установлен или на компьютере есть только более старая версия, `uv` автоматически скачает подходящую версию, создаст окружение `.venv` и установит зависимости из `uv.lock`.

Из корня проекта достаточно выполнить:

```bash
uv sync --locked
```

Если нужна конкретная версия Python, можно выполнить `uv sync --locked --python 3.14`. При переносе на другой компьютер окружение `.venv` создаётся заново той же командой.

Для сбора и загрузки PDF достаточно установленных Python-зависимостей.

## Быстрый запуск

### Веб-интерфейс

```bash
uv run --locked ui
```

Интерфейс доступен по адресу `http://127.0.0.1:8765`. Для другого порта можно добавить `--port 8766`. Сервер останавливается через Ctrl+C. Также доступен запуск через `uv run python -m ekb_parser.ui`.

### Пробный сбор из консоли

```bash
uv run --locked python -m ekb_parser collect \
  --config configs/yageo/capacitors.json \
  --group aluminum \
  --output data/yageo/runs/aluminum \
  --max-pages 3
```

Команда сохраняет до трёх страниц оксидно-электролитических конденсаторов. При повторном запуске с тем же запросом и папкой сбор продолжается со следующей сохранённой позиции.

## Работа в веб-интерфейсе

В верхней панели можно выбрать сайт и сохранённый сбор. Подключён YAGEO. Пункт «Другой сайт» оставляет доступ к общей матрице и журналу инструментов.

| Страница | Возможности |
| --- | --- |
| **Каталог** | Поиск по артикулу, производителю и серии, карточки компонентов, статистика заполненности и выгрузки CSV, JSONL, SQLite и ZIP. |
| **Сбор каталога** | Выбор категории и подкатегории, настройка лимитов, запуск и продолжение сбора, просмотр прогресса. |
| **Результаты** | Выгрузка файлов, пакетная загрузка PDF и удаление сбора удержанием кнопки. |
| **Компоненты** | Просмотр параметров выбранного сбора, отчёт о заполненности и импорт дополнений из JSON. |
| **Источники** | Настройка категорий YAGEO, получение фильтров, обновление матрицы и сопоставление параметров. |
| **Журнал** | Вывод задач сбора, загрузки PDF и вспомогательных инструментов. |

«Каталог» работает без ручного выбора набора. Для каждой подкатегории он берёт сохранённый сбор с наибольшим количеством компонентов в соответствующей выборке. При равном количестве используется более свежий сбор. Общий ZIP включает выгрузки подкатегорий, индекс архива, матрицу и правила сопоставления. PDF можно открыть из карточек компонентов.

## Сбор и конфигурация YAGEO

В `configs/yageo/` хранится по одному файлу на категорию. В `capacitors.json` и `resistors.json` подкатегории перечислены в массиве `groups`. Параметр `--group` принимает ключ подкатегории. При явном `--config` без `--group` собираются все подкатегории файла.

| Параметр | Действие |
| --- | --- |
| `--output` | Папка сборки и её состояния. При изменении запроса или размера страницы нужна новая папка. |
| `--max-pages` | Лимит страниц за текущий запуск. Значение `0` снимает лимит. |
| `--max-parts` | Лимит уникальных компонентов во всём сборе, включая сохранённые при предыдущих запусках. |
| `--no-export` | Сохранение состояния в SQLite без формирования файлов выгрузки. |

```bash
uv run python -m ekb_parser status --output data/yageo/runs/aluminum
uv run python -m ekb_parser export --output data/yageo/runs/aluminum

uv run python -m ekb_parser filters \
  --config configs/yageo/capacitors.json --group aluminum \
  --save data/yageo/metadata/aluminum_filters.json
```

Строки страницы и позиция продолжения записываются одной транзакцией. При остановке или сетевой ошибке уже сохранённые страницы доступны в SQLite. Если при продолжении меняется заявленное сайтом количество строк, сбор останавливается. Пагинация по offset оставляет риск пропусков при изменении каталога с тем же общим количеством записей.

### Добавление подкатегории

В «Источниках» можно добавить подкатегорию в существующую категорию или создать новую категорию вместе с первой подкатегорией. Для новой категории нужны название, ключ файла и адрес страницы каталога. Например, ключ `inductors` соответствует файлу `configs/yageo/inductors.json`.

В поле `base-part` нужен полный Request URL из Network или путь `/search/query/base-part/…`. «Проверить запрос» показывает декодированные фильтры. При сохранении приложение берёт идентификатор категории и фильтры. Параметры пагинации и сортировки из ссылки отбрасываются.

Пример подкатегории из `configs/yageo/capacitors.json`.

```json
{"key": "aluminum", "name": "Конденсаторы оксидно-электролитические", "query": {"1": 1, "79": [397]}}
```

Здесь `1:1` обозначает категорию Capacitors, а `79:[397]` — тип Aluminum. ID значения фильтра может отличаться от ID подгруппы в карточке. Сбор использует записи уровня `base-part`. Варианты упаковки и суффиксов отдельно не раскрываются.

## Данные и выгрузки

| Файл или папка | Содержимое |
| --- | --- |
| `crawl_state.sqlite3` | Рабочая база сбора. Содержит компоненты, группы, позицию продолжения, состояние загрузки PDF и импортированные дополнения. |
| `collection_config.json` | Снимок конфигурации сбора. |
| `parts.jsonl`, `parts.csv`, `articles.txt` | Выгрузка компонентов и список артикулов. В JSONL каждая строка представляет отдельный JSON-объект. |
| `documents.jsonl`, `datasheets/` | Уникальные ссылки на даташиты и скачанные PDF соответственно. |
| `group_parameters.json` | Найденные параметры по группам с ID, примерами и частотой заполнения. |
| `summary.json`, `last_run.json` | Прогресс, причина остановки и ошибки последнего запуска. |

При открытии сохранённого сбора интерфейс читает рабочий SQLite. Компоненты имеют ключ `(source, source_id)` и могут входить в несколько групп. Для параметра сохраняются исходное `value` и отображаемое `formatted_value`, например `0.000033` и `33 uF`.

### Загрузка даташитов

В «Результатах» сначала нужно открыть сбор, затем можно запустить задачу «Скачать datasheet». PDF сохраняются на компьютере, где запущен сервер. Для скачивания из консоли доступна команда ниже. Параметр `--max-documents 2` ограничивает число попыток загрузить новые документы.

```bash
uv run python -m ekb_parser datasheets --output data/yageo/runs/aluminum --max-documents 2
```

Имя PDF соответствует SHA-256 содержимого, поэтому одинаковые документы сохраняются один раз. `datasheet_downloads.jsonl` содержит URL, локальный путь, хеш и статус, а `last_datasheet_run.json` — итог запуска. При повторной загрузке существующие PDF пропускаются, а отсутствующие файлы и ошибки обрабатываются снова.

## Требования аналитиков

HTML-листы хранятся в `project_files/analytics_data/`. Конвертер формирует из них `data/analytics/requirements.json`. После изменения HTML нужно обновить JSON. Если JSON отсутствует, требования читаются из HTML.

```bash
uv run --locked python -m ekb_parser convert-requirements
uv run --locked python -m ekb_parser coverage \
  --output data/yageo/runs/aluminum --save coverage.jsonl
```

В матрице `required` означает обязательное поле, `fixed` — готовое значение, `excluded` — исключённое поле, `unspecified` — отсутствие требования. Процент заполненности равен доле заполненных обязательных полей среди компонентов с оценкой. Компоненты без оценки считаются отдельно. В сводке каталога запись учитывается в каждой подкатегории, к которой она принадлежит.

### Сопоставление параметров каталога

В «Источниках» нужно открыть лист матрицы, выбрать обязательную ячейку и сопоставить её с параметром подкатегории YAGEO. ID можно найти в «Фильтрах каталога» или в `parameterId` ответа `base-part`. Множитель переводит числовое `value` в единицы поля. Для текста используется множитель `1`.

Правила сохраняются в `data/analytics/catalogue_mappings.json` и применяются к существующим сборам с тем же запросом подкатегории. Ранее выгруженный отчёт JSONL после изменения правил нужно сформировать заново. Если соответствие пока неизвестно, можно отметить поле «Дозаполнить позже».

Для алюминиевых, керамических и плёночных конденсаторов уже есть правила ёмкости (ID 6) и номинального напряжения (ID 10). Для однозначно сопоставленных подкатегорий резисторов есть правило номинальной мощности (ID 271). Подкатегория `Metal` требует уточнения по конкретному изделию.

### Дополнение параметров из PDF

Ручные дополнения можно импортировать через «Компоненты» или CLI. Для пакетов подходит папка `data/analytics/supplements/<сбор>/`. В JSON-массиве нужен строковый `source_id` из карточки или `parts.jsonl`, точное название поля матрицы, значение в нужных единицах и основание. Необязательное `group` в формате `["Лист", "Группа"]` позволяет уточнить классификацию.

```json
[
  {
    "source": "yageo",
    "source_id": "33810302",
    "fields": {
      "Tмн, ч": {"value": 20000, "evidence": "Отчёт серии AA, стр. 4"}
    }
  }
]
```

Значения приведены как пример формата. Импорт обновляет переданные поля. Значения `fixed` берутся из матрицы.

```bash
uv run python -m ekb_parser import-supplements \
  --output data/yageo/runs/resistors-1606_20261118_101232 \
  --input data/analytics/supplements/resistors-1606_20261118_101232/aa.json
```

Массовая обработка использует отдельный пайплайн `pdf-enrichment`. Он готовит очередь, принимает результаты внешнего извлекателя и проверяет кандидатов перед записью в SQLite. [Форматы и команды обработки PDF](docs/pdf_enrichment.md)

## Перенос на другой компьютер

```bash
python3 scripts/package_project.py
```

Скрипт создаёт `dist/ekb-parser.zip`. В архив входят код, конфигурации, lock-файл, документация, тесты, таблицы аналитиков и рабочие данные из `data/`, включая сохранённые сборы и их даташиты. SQLite копируется согласованным снимком. Временные файлы, журналы, виртуальное окружение и метаданные Git исключаются.

Перед упаковкой нужно дождаться завершения сбора и загрузки PDF, чтобы выгрузки и файлы документов соответствовали базе. Для другого пути ZIP можно указать `--output`. На новом компьютере нужно распаковать архив в отдельную папку и создать окружение по разделу «Установка».

## Структура проекта

| Путь | Назначение |
| --- | --- |
| `ekb_parser/core/` | CLI, сбор, хранение, экспорт, проверка заполненности и обработка дополнений. |
| `ekb_parser/sources/` | Контракт, реестр и адаптеры сайтов. |
| `ekb_parser/web/` | Flask API, шаблоны, стили и логика веб-интерфейса. |
| `configs/<source>/` | Категории и фильтры источника. |
| `data/<source>/runs/` | Рабочие базы, выгрузки и PDF по сборам. |
| `data/<source>/metadata/` | Сохранённые фильтры каталога. |
| `data/analytics/` | Скомпилированная матрица и правила сопоставления. |
| `project_files/analytics_data/` | Исходные HTML-листы аналитиков. |
| `docs/`, `tests/` | Документация и офлайн-тесты. |

Реестр адаптеров используется CLI и веб-интерфейсом. Для подключения следующего сайта нужен адаптер с запросами каталога и разбором ответа. [Добавление источника](docs/adding_source.md)

## Проверки

```bash
uv run --locked python -m unittest discover -s tests -v
```

Тесты работают офлайн и проверяют сбор, возобновление по сохранённой позиции, веб-API и импорт дополнений.
