# Добавление сайта

## Что общее, а что зависит от сайта

`core/` отвечает за лимиты, последовательный обход, контроль прогресса, транзакции, экспорт и загрузку PDF.
`web/` только редактирует конфигурацию и запускает тот же CLI отдельным процессом.
URL, методы запросов, JSON/HTML, поля и правила фильтров принадлежат `sources/<site>/adapter.py`.

Пока подключён один реальный сайт — YAGEO. Второй источник не появляется от ввода одного URL:
сначала нужно реализовать его адаптер и проверить на фактических ответах сайта.

## Порядок добавления

1. Создать `ekb_parser/sources/<site>/__init__.py` и `adapter.py`.
2. Унаследовать адаптер от `SourceAdapter` в `sources/base.py`.
3. Указать `key`, `name`, `website`, `allowed_domains`, `max_page_size`, `default_groups`.
   В allowed_domains включить документированные домены сайта и CDN, необходимые для запросов и PDF.
4. Реализовать `page_request(query, offset, page_size)` и `parse_page(response)`.
   Запрос — объект Scrapy Request: можно использовать GET, POST, JSON и заголовки.
   Разбор может использовать `response.json()`, CSS или XPath.
5. По необходимости реализовать `metadata_request(query)` и `parse_metadata(response)`.
   Метаданные возвращаются как `Metadata(expected_count, raw)`.
   Если метаданных нет, оставить `metadata_request` со значением None: сбор остановится на короткой/пустой странице.
6. Добавить проверку фильтров в `validate_query`. Настройки всего адаптера доступны в `self.options`;
   для них переопределить `validate_options`. Не хранить пароли и токены в обычных JSON-конфигах.
7. Импортировать класс и вызвать `register_source(NewAdapter)` в `sources/registry.py`.
8. Положить рабочие конфиги в `configs/<site>/*.json`.
9. Добавить тесты на реальные сохранённые/обезличенные примеры ответов и проверить две разные страницы.
10. Перезапустить локальный UI: сайт появится в выборе источника, конфиги — под ним.

Ядро, SQLite, экспорт и UI для этого менять не нужно.

## Контракт записи

`parse_page` возвращает список словарей, соответствующих `core/models.py`:

```python
{
    "source": "new_site",               # совпадает с ключом адаптера/конфига
    "source_id": "123",                 # стабильный ID источника, строка
    "part_number": "PART-123",
    "manufacturer": "Manufacturer",
    "series": "Series",                 # может быть None
    "source_url": response.url,
    "retrieved_at": "2026-11-17T12:00:00Z",
    "datasheet_url": "https://vendor.example/document.pdf",  # необязательно
    "parameters": [
        {"source_parameter_id": "voltage", "name": "Voltage",
         "value": "10", "formatted_value": "10 V"}
    ],
    "raw": {"original": "source data"}
}
```

Нестандартные поля допускаются и сохраняются. ID параметров могут быть строками или числами.
Отсутствующее значение не заменять нулём. Имя производителя и артикул требуют отдельной нормализации
перед будущим объединением результатов разных сайтов в PostgreSQL.

## Конфигурация

```json
{
  "source": "new_site",
  "options": {},
  "page_size": 50,
  "download_delay": 2,
  "groups": [
    {"key": "capacitors", "name": "Конденсаторы", "query": {"category": "capacitors"}}
  ]
}
```

`query` передаётся адаптеру без предположений YAGEO о числовых ключах вроде `1` и `79`.
`options` входят в идентификатор конфигурации и не могут меняться при продолжении существующего сбора.
Для старых конфигов YAGEO отсутствие options и пустой options дают прежний идентификатор: перенос папок
не сбрасывает прогресс.

## Ограничения текущего общего обхода

- Используется offset: количество сохранённых строк. Адаптер должен уметь получать записи с произвольного
  offset, в том числе после остановки посередине страницы из-за max-parts. Для сайтов с номерами страниц
  адаптер может запросить нужную страницу и отрезать уже сохранённый префикс.
- Для cursor-only API понадобится отдельная стратегия состояния курсора; она пока не реализована.
- В одной группе повторение ID между страницами считается ошибкой нестабильного обхода.
- Если известно общее число строк, пустой ответ до его достижения — ошибка, а не успешное завершение.
- Изменение источника во время обхода offset может давать пропуски даже при неизменном общем числе записей.
- Сайт, данные которого доступны только после выполнения JavaScript, может потребовать отдельного механизма загрузки в адаптере.

Для проверки независимости от YAGEO есть офлайн HTML-адаптер в `tests/test_sources.py`. Он доступен только
в тестах и не отображается как поддерживаемый реальный сайт.
